# Native fallback integration
**Goal:** Complete the native host ladder with legacy retry/escalation policy, per-rung accounting and crash-safe active-model recovery; keep the pinned Pi engine contract unchanged.
**Scope:** L; three ordered implementation units below. No babysit ticket is in scope on `main`; size is recorded here. Other provider ports remain part of the parent goal, outside this integration unit.
**Approach:** A concrete host-owned ladder binds each resolved tier's model, callbacks, dispatcher, capabilities/window and pricing; selection must switch these together, using `internal/runtime/native_ladder_binding.go` and `tiers.go`.
**Unit 1 — binding/selection (integrated):** `native_ladder_selection.go` scopes selection to one agent/session; retain full model identity, provider row and rung ordinal in the host record, never credentials. Atomic binding, row-scoped refresh, failed/stale commits, restore identity and cancelled-successful-write tests pass. The built-in native runner constructs full configured ladders.
**Unit 2 — attempts (integrated):** Each attempt uses native request observation; buffer only replay-safe metadata, preserve partial pointer identity, honor per-rung retry/Retry-After, stop on cancellation or committed visible content, and retain the successful rung. Tests cover failures before/after text, thinking and tool events, usage of failed attempts and rotated credentials.
**Unit 3 — persistence (integrated):** Commit active selection before admitting effects from the successful response; apply the selected model to host-visible Agent state, and replay/validate the selection against current bindings before a resumed request. Coordinator/session tests cover selection persistence, tool admission, agent-end checkpoints, append/lease failures and changed bindings. Full runner HTTP tests additionally cover retained fallback on resume, child-owned selection, changed endpoint rejection and failed selection append preventing tool effects.
**Unknowns (derived):** `prepareRequest` changes only the local loop config, not persistent Agent model (`agentcore/engine/loop.go:102`, `testdata/generate-agent-fixtures.ts:57`); a dispatcher-only fallback would persist the wrong model.
**Caller constraint (implemented):** Candidate prepareRequest can change context/tools and thinkingLevel. The optional Go-only engine AdmitRequest callback installs that prepared request before consuming its stream; the nil path retains Pi's preparation pipeline. Provider-only transform/convert views remain separate. Differential loop/Agent checks still match the pinned source.
**Unknowns (derived):** `PiSession.event` checkpoints at `agent_end`, while `recoverPiState` also replays message/effect events (`internal/runtime/pi_session.go`); a crash before that checkpoint requires an explicit replayable selection record and ordering with effect receipts.
**Credential ownership (implemented):** Native BuildParams.RefreshProviderKey receives provider row, vendor and endpoint. The runner refreshes known rows from the workspace book and requires matching route identity; rowless hosted bindings require one unambiguous route/key. BindPi still calls its bound vendor callback, but each native rung's wrapper captures that rung's identity. Pool acquisition stays inside the native stream and bypasses static refresh.
**Unknowns (derived):** Legacy `Agent.reason` keeps the successful rung and refuses escalation after a committed stream (`agentcore/turn.go:274`); native engine returns immediately after an error message, so fallback belongs inside host attempt orchestration rather than replaying a whole agent turn.
**History:** Commit `2da927e` introduced Pi host session/children/compaction/model paths together; verify forks and compaction against selected-rung identity, not only parent prompt success.
**Verify:** `go test -race -tags pi_native ./internal/runtime ./ai ./agentcore ./agentcore/engine ./telemetry/... -count=1 -timeout=120s`; `go vet -tags pi_native ./internal/runtime ./ai ./agentcore ./agentcore/engine ./telemetry/...`; all new selection crash/resume cases; pinned Agent oracle unchanged.

**Caller integration complete for built-in native providers:** Main runner and auxiliary summaries construct independent multi-rung ladders with per-rung row refresh. Ambiguous vendor-only custom refresh is rejected for same-vendor/different-row or route bindings. Admission preserves the host catalogue while each provider request suppresses declarations for a tool-disabled rung; committed capability hooks prevent hallucinated tool effects. Full runner HTTP/fork/resume/compaction/persistence cases pass. Explicit custom stream overrides and worker calls retain their existing paths and configured-fallback rejection. Other provider/OAuth ports, full parity audit, default switching and bridge retirement remain outside this unit.

**Runner verification:** `TestNativeRunnerFallbackCompactionToolAndResume` exercises independent summary escalation, row credentials, tool effect, usage/traces, opaque native history and resume on the retained fallback. `TestNativeRunnerFallbackChildOwnsSelection` verifies a child starts from primary, escalates independently and journals its own selection. `TestNativeRunnerFallbackPersistenceFailurePreventsToolEffect` checks selection append failure prevents effects and releases the lease. `TestNativeLadderToolCapabilitiesPreserveHostCatalogue` covers primary/fallback tool suppression, explicit empty catalogues and deny-all host policy. Unsupported forced tool choices remain binding errors; broader legacy capability equivalence is not claimed.

**Child ownership implemented:** Each piForkRunner invocation clones immutable model/options bindings into a fresh ladder at primary/generation zero; resume applies only that child journal. Credential refresh/pool services and passive trace sinks remain shared. Parallel child tests prove parent selection cannot redirect child model/credential routing or overwrite child generations.
**Request scope implemented:** Native onPayload uses the provider request context. Candidate prepare/transform/convert/get-key/payload hooks and dispatcher routing select an owner/generation-bound attempt context without changing committed state. Foreign/stale scopes are rejected; tool callbacks use only committed selection. Host prepareRequest rewrites known prior/candidate model identity before outer host hooks, validates their model result, and merges the selected model into the returned update. Session admission applies these hooks for each attempt.

**Attempt option binding implemented:** openNativeAttempt refreshes the scoped row credential for every attempt, removes inherited API keys before null/pool bindings, replaces the spread model and configured per-rung output cap, preserves request context and explicit non-binding controls, and routes onPayload through session hooks. Real HTTP ladder tests use this path. Admission merges the configured stream options with loop runtime controls. Inspection of NativeAgent.configure confirms maxTokens/streamOptions are not runtime settings; per-rung configured caps remain authoritative.

**Per-attempt trace implemented:** openNativeAttempt uses native request observation with original typed admission failures retained for retry. Trace packets carry request ID, model, rung/provider row, generation at admission and per-rung pricing knowledge; failed and successful attempts remain distinct and pricing projection uses the attempt flag. Existing public Pi admission-error wording is unchanged. Admission bypasses the outer logical-request observation; integrated tests confirm one trace per provider attempt.

**Attempt usage implemented:** RunPi installs session-owned accounting hooks. Every settled attempt contributes native usage with its own pricing flag; the coordinator registers only the published terminal before release. message_end validates and consumes that handoff without counting it again. Only the engine-owned thinkingLevel annotation is excluded from equality. Identical responses on later requests still count independently. Tests run the real native engine with failed-primary/fallback and repeated successful messages, and verify discarded failures stay out of conversation history.

**Request compaction window implemented:** Compaction resolves the committed or candidate binding on each transform, clamps from the original host policy, and retains exact-prefix summary reuse. Testing a smaller candidate cannot permanently shrink the primary budget. Foreign/stale scopes fail before summary work; native history and complete tool batches remain intact. Admission invokes this transform on each candidate's prepared context before convertToLlm.

**Candidate preparation implemented:** prepareNativeAttempt clones the untransformed logical request, applies scoped prepareRequest, then scoped transformContext/convertToLlm, and returns prepared native context separately from normalized provider transcript/options. It preserves opaque fields, default custom-role filtering, thinking updates, and Pi's rule that prepareRequest does not append update.Messages. The no-update path retains installed Go tool argument preparers/executors; the runner ask/resume test caught and verifies this boundary. Tests compare transcript/options and callback order against a real engine request; repeated candidates start from the original view and do not publish state.

**Preparation failure boundary implemented:** Preparation, credential, and scope-validation errors retain their original cause inside a concrete nativePreparationError. Retry orchestration stops on that origin before retry/escalation, even for a typed HTTP 503 returned by a host callback. Actual provider admission failures remain retryable. Tests cover each prepare/transform/convert/get-key stage with no provider dispatch or model-selection write.

**Admission and abort implemented:** The coordinator returns the candidate's prepared context at durable commit while the provider continues streaming. Loop consumption uses that context and reasoning before tool execution/final annotations. RunPi tests prove retained fallback across a tool turn, selection before effect receipts, correct usage, and no duplicate outer trace. Abort drains the native terminal and producer settlement with an uncancelled reader while the provider's signal remains cancelled. Before/after-commit tests preserve native aborted content and all attempt usage without selecting another rung. Children inherit admission policy but retain independent ladders.

**Row refresh wired:** Runner.execute supplies a native row/route refresh callback alongside the unchanged legacy vendor callback. Native parent and summary bindings capture their own row identities; children inherit immutable scoped callbacks. Deleted rows, changed vendor/endpoint, empty keys and ambiguous rowless keys fail before provider dispatch without escalation. Hosted-default resolution clears stale primary provider IDs because those workspace rows do not own the host key; explicit fallback row IDs remain intact. Real HTTP tests rotate a same-vendor primary key across retries, escalate to a different row, resume on its rotated key, and stop before dispatch after route/key revocation. The full runner compaction test verifies distinct parent/summary row credentials and forbids vendor-only lookup.
