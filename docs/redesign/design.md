# UI concept: product overview before agent configuration

Status: proposed; sample data only. Designed for a builder operating a web/app product. Primary job: understand whether people arrive, activate and return, then choose the next useful investigation.

The standalone [concept.html](concept.html) is a disposable design artifact that links `web/app/globals.css` directly — tokens are consumed from the canonical stylesheet, never copied — with visual patterns mapped to Astryx/AgentRay components. Open with `open docs/redesign/concept.html`. It includes an overview, Data, Plans and Agents concepts, with a visible sample-data label and first-run / delayed-source states. Following the user's design-and-plan-only instruction, no frontend route or production component is added.

Layout: project sidebar; page title and context; one headline metric strip; activity trend; activation/retention details; a concise next-step panel. Source freshness stays visible. Detailed SQL and agent traces are secondary. Primary navigation changes from backend layers to owner tasks. Agent Garden nests under Agents as optional, lower priority.

Implementation mapping: Astryx AppShell, SideNav/SideNavHeading/SideNavItem, Card, Heading, Text, VStack/HStack and Button; AgentRay PageShell, AutoGrid, StatsStrip, Chart and BarRows. A later implementation can adapt AgentRay's authenticated AppShell to this IA. Colors, spacing, fonts and focus follow globals.css. No new brand tokens or UI library. The HTML only imitates these components; it is not production component code.

NEW composition: a task-specific external-agent handoff, showing the project task and expected result; this fills the gap between existing internal-chat actions and external-agent workflows. In the prototype it is explanatory copy only, not a configured connection. The final product must generate client-appropriate instructions, private credential setup, scope display and a connection test.

State contracts: first run explains installation and verification; loading retains layout and announces refresh; no matching results offers filter reset; stale sync retains timestamped last-known figures and explains which metrics are affected; fatal query error offers retry; missing access identifies the needed role; success confirms the artifact/event. Unconfigured activation/revenue and immature retention have explicit labels rather than zeroes.

Responsive/accessibility: production sidebar becomes the library's mobile navigation; the standalone concept uses wrapping anchor navigation on mobile. Content grids collapse to one column; table overflow stays local; controls have visible labels, keyboard focus and at least 44px targets. Trend has a textual equivalent. Status uses words as well as color. No new animation. Prototype anchor links identify the selected section and preserve browser history.

The prototype illustrates IA and the core value moment; it is not a complete dashboard editor, SDK wizard or pipeline builder. Those flows use the contracts in strategy.md and are implemented in their delivery slices.

Design decision: this proposal changes DESIGN.md's chat-first and Runtime/Channels/Workloads IA because the user's stated first use case is SDK integration followed by basic analytics. The existing visual system is retained. The root design contract is not rewritten until this direction becomes implementation scope.
